## 一、這個專案在做什麼、現在到哪裡

把幾乎任何檔案（Markdown、程式碼、Word、PPT、Excel、PDF、圖片影音、
Jupyter……）拖進瀏覽器，轉成一份**自帶樣式、可離線開啟的 HTML 閱讀台**。

```text
本體    md2deck-next/public/studio.html —— 2337 行、182KB 的單檔引擎
外殼    md2deck-next/ 的 Next.js —— 總共 181 行，實際上只是一個
        把 /studio.html 塞進 iframe 的殼（StudioFrame.tsx 共 10 行）
測試    test/studio.test.cjs（278 行）
```

**這個專案的選型是對的，而且對得很徹底**：純前端、零後端、檔案不上傳。
一個做這件事的工具本來就不該有伺服器——沒有伺服器就沒有資料外洩的路徑，
這是**結構上的保證**，不是承諾。

那份測試也值得單獨說：單檔 HTML 沒有模組匯出，它用
「正則挖出純函式 → eval → 配 jsdom 斷言」加上對兩層 JS 各做語法檢查。
那是對單檔引擎做單元測試的正確務實作法，不是敷衍。

**但它現在有一個問題，正好打在自己最核心的那句承諾上。**

## 二、最該先修的三件事

### 1. 🔴「檔案完全不上傳」這句話，目前由 cdnjs 決定成不成立

`studio.html` 從 `cdnjs.cloudflare.com` 載入**至少六支**腳本：

```text
marked 12.0.2                  Markdown 解析
highlight.js 11.9.0            語法高亮
dompurify 3.0.9                ⚠️ 消毒器本身
mermaid 10.9.0                 流程圖
KaTeX 0.16.9 ×2                數學公式
（另有 jszip / mammoth / xlsx / pdf.js 的 CDN 路徑）
```

而：

```text
integrity=（SRI）   0 個。一個都沒有
CSP                 有寫，但在 md2deck_deploy/_headers 裡是**註解掉的**
                    （每一行前面都有 #）
next.config.mjs     只有 nosniff / Referrer-Policy / X-Frame-Options /
                    Permissions-Policy，沒有 CSP
```

**這代表什麼**：使用者把一整個資料夾的文件拖進來——可能是合約、
可能是原始碼、可能是病歷。那些檔案確實沒有上傳到**你的**伺服器。
但頁面上跑著六支從第三方網域即時抓來的腳本，
而它們與那些檔案在同一個 JS 環境裡。

cdnjs 被投毒（或被 DNS 劫持、或被中間人替換）的那一天，
注入的程式碼**讀得到使用者拖進來的每一個位元組**，
而且可以自己 `fetch` 出去——沒有 CSP 的 `connect-src` 攔它。

⚠️ 更尖銳的一點：**DOMPurify 自己就是從 CDN 來的**。
XSS 的防線由一支你不控制的檔案提供，那條防線的強度等於 cdnjs 的強度。

**怎麼修**（依成本由低到高，前兩步一天內做得完）：

```text
第一步（最便宜、擋掉最大宗）
  把 CSP 從註解裡放出來，並且**把 connect-src 收成 'none'**。
  這個工具沒有任何理由發出網路請求——它是純前端、零後端。
  connect-src 'none' 的意思是：就算腳本被換掉，它也送不出去。
  這一條的價值比其他所有加起來都高，因為它擋的是「外洩」本身，
  而不是「被替換」。

第二步 加 SRI
  每個 <script src> 加 integrity="sha384-…" crossorigin="anonymous"。
  檔案被動過就不執行。cdnjs 的頁面直接提供這串。

第三步 自己託管
  pdf.js 已經自架在 public/vendor/pdf/ 了——把其餘六支照同樣方式搬進來。
  搬完之後 script-src 可以收成 'self'，而 README 那句
  「部署後不依賴外部 CDN」才會變成整體成立，
  而不是只對 pdf.js 成立。
```

⚠️ **README 目前的說法要一起改。** 它寫「pdf.js 已內建自架……
部署後不依賴外部 CDN」，讀起來很像整個工具都不依賴 CDN，
而實際上只有 pdf.js。一句對一半的安全說明比不說更危險——
因為讀的人會據此決定要不要把敏感檔案拖進去。

### 2. 引擎有兩份，而且已經分岔了

```text
md2deck-next/public/studio.html   2337 行  182KB
md2deck_deploy/index.html         1018 行   78KB
```

兩份的 `<title>` 一樣（都是 md2deck Studio），**md5 不同，行數差 1319 行**。
也就是說：deploy 那一份落後很多個版本，而沒有任何東西在說這件事。

這是「兩份真相」最典型的樣子。它不會報錯，兩邊各自都跑得起來，
只有實際打開線上版才會發現「我修好的那個 bug 還在」。

**怎麼修**：先決定哪一份是本體（看起來是 `public/studio.html`），
另一份改成**建置時複製過去**，不要手動同步。
然後加一條守衛——最小可行版本是一行：

```bash
# npm test 裡多跑一行
cmp -s md2deck-next/public/studio.html md2deck_deploy/index.html || exit 1
```

⚠️ 加完之後**故意改壞一次驗它**：在其中一份加一個空白行，
確認真的紅了。這一條在 1page 是硬性規矩——
「守衛通過不等於守衛有效」，那邊一天之內抓到過三個名不副實的綠燈。

### 3. 那份測試很好，但沒有任何東西在問「有沒有漏掉」

`studio.test.cjs` 驗的是挑出來的幾個純函式。而這個引擎宣稱支援
**二十幾種副檔名**，每一種都有自己的拆解邏輯。

沒有任何地方在問：**清單裡有沒有哪一種格式沒有被測到**。

這是 1page 反覆踩到的第一種毛病的形狀：不是「測試不夠多」，
是「沒有東西在數」。逐一補「csv 要有測試」的話，
下次加一種格式又要記得補；反過來問的話它自己會發現下一次。

**怎麼修**：引擎裡一定有一張副檔名 → 處理器的對照表（或 switch）。
把它挖出來，測試改成：

```text
for (每一個宣稱支援的副檔名) {
  丟一個最小樣本進去，斷言「有產出，而且不是那個 fallback 附件卡」
}
刻意不測的要進具名清單並寫理由
```

`.pptx` / `.xlsx` / `.pdf` 這種需要二進位樣本的可以列進例外，
但**要寫下理由**，不是靜靜地不測。

## 三、可以從 1page 搬過去的（已經驗證過，不是想法）

```text
CSP 的 connect-src         1page 的 lib/security/csp.ts。
                           純前端工具的最強一條就是 connect-src 收死
「反過來問」型的守衛        上面第 3 點。不要列「A 要有 B」，
                           要問「清單裡有沒有哪一個沒人做」
故意改壞驗守衛             每加一個守衛就把程式改壞一次，
                           改壞的方式要對應它宣稱要擋的那件事
比對原始碼前先去掉註解      `_headers` 那份 CSP 就是被註解掉的——
                           任何「檢查 CSP 有沒有寫」的腳本都會誤判成有。
                           1page 因為同一個原因造成過一次假通過、一次假失敗
稽核「有沒有真的送出去」    不要檢查原始碼裡有沒有寫 CSP，
                           要 curl 一次線上網址看標頭。1page 的
                           audit-security 就是這樣寫的
```

## 四、不建議做的事

```text
❌ 把單檔引擎拆成模組        2337 行聽起來像該拆，但**單檔正是這個產品的一部分**：
                            產出的閱讀台要能離線開啟、要能單檔寄給別人。
                            拆完之後要嘛加建置步驟，要嘛失去那個特性。
                            現在那份測試已經證明「單檔也測得動」

❌ 加後端                    零後端是這個工具唯一真正的差異化。
                            一旦有伺服器，「檔案不上傳」就從結構保證
                            降級成一句承諾，而承諾要靠稽核來證明

❌ 換掉那份「挖原始碼 eval」  它看起來很土，但它解決的是真問題，
   的測試作法                而且註解裡就寫明了為什麼。換成 import
                            需要先拆檔案，而拆檔案見第一點

❌ 追求支援更多格式           已經支援二十幾種，而且有 fallback 附件卡
                            （什麼都收得下）。下一格式的邊際價值遠低於
                            「現有二十幾種有沒有測到」
```

## 五、順序

```text
第一步  CSP 放出來，connect-src 'none'。一行設定，擋掉最大的那個風險
第二步  README 那句「不依賴外部 CDN」改成只對 pdf.js 成立的說法
第三步  兩份 studio 收成一份 + 一行 cmp 守衛（並故意改壞驗過）
第四步  六支 CDN 腳本加 SRI，然後逐步自架
之後    副檔名覆蓋率反過來問的守衛
```

第一步與第二步加起來不到一小時，而它們處理的是這個工具
**最核心的那句承諾**。其他都可以等。
